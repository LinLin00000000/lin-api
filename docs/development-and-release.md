# Lin API 开发与发布规范

> 本文是 Lin API 项目级开发与发布流程真源。公共 CI 与 GHCR 镜像构建已实现；私有脚本、测试环境与定时发布以各自运行验收为准，不得仅凭本文声称已经部署。

## 最小结构

- 两个环境：DEV 测试站、生产站；不增加第三套常驻 staging。
- 两个长期分支：`dev`、`main`；功能使用短期 `feature/*`（已有 `feat/*` 无需为命名重建）。
- Go 后端和 React 前端使用同一 Dockerfile 构建、整体更新。不默认使用 HMR 或独立前端开发服务器。
- 使用 GitHub CI 和一个镜像仓库；生产按不可变 digest 部署，不挂载源码、不追踪浮动 tag。

## Agent 默认工作流与授权

1. 明确一整个功能的范围，在隔离工作树完成代码、相关测试和必要审查。
2. 检查共享仓库 dirty paths、远端和合并冲突；不覆盖其他 Agent 的修改。符合既定功能范围、检查通过后，Agent 默认合入 `dev` 并更新测试站，无需再次询问“是否更新 DEV”。多个 Agent 并行开发，但共享 dev 合并/部署必须串行。
3. 更新后验证页面、健康、认证和受影响功能，报告可测试版本。仅提交代码或 CI 成功不等于预览更新成功。
4. 功能完成不自动授权合入 `main`。产品验收和请求合入 main 是独立的源代码接纳边界。
5. **一旦按授权合入 main，即表示允许该版本在下一次凌晨维护窗口自动发布**，不再增加逐版本发布审批。用户明确要求立即发布时可绕过时间等待，不能绕过检查与数据安全门槛。
6. 新的权限扩大、公开暴露、不可逆迁移或未覆盖的重大风险仍需说明并停止危险动作；不得用“自动发布”绕过这些边界。

`main` / `dev` 禁止强推。PR 或等价的受保护合并检查必须覆盖合并结果。发布批次使用正常 merge 保留 dev/main 祖先关系，不对长期分支反复 squash/rebase；feature PR 可 squash。main 热修复回合 dev。上游引入的改动单独列清范围，不能夹带在功能中不作说明；按 UPSTREAM.md 审查。

## 测试数据与真实调用

- DEV 使用独立数据库、Redis、会话密钥、数据目录及应用端口；绝不连接生产可写数据库，不复制生产 Redis。
- 测试可以复用生产中的上游渠道定义、模型、价格和必要上游凭据；凭据只在私有受控执行链中流转，不输出到聊天、日志、Git、CI artifact 或镜像。
- 真实调用是可选的功能验收步骤，会产生真实费用；启动或更新 DEV 不得自动全渠道探测、重放生产任务、批量调用或运行付费基准测试。仅对受影响渠道/模型做必要且有界的调用，明确目标和预算边界；无预算时不自行扩展高费用或批量测试。
- 不导入客户 API Key、登录会话、真实支付/通知动作或待执行生产任务。独立测试管理员和测试 API Key 留在 DEV。
- 默认按 allowlist 同步渠道、模型、价格等配置，不把完整生产数据库 clone 作为常规路径。外部动作设置不在 allowlist 中。关系、schema、加密方式必须在实现时检查；不凭表名猜测。

## 更新、停启与配置同步

- `preview update`：更新到已检查的 dev 精确 SHA/digest；测试站关闭时自动启动；保留测试数据和修改。
- `preview stop/start`：关闭/启动测试栈，不删卷；start 不隐式刷新或重置数据库。
- `preview status`：显示运行版本、健康和最后配置同步标识；新一轮开发先检查状态及配置是否变化，不只按闲置天数判断。
- `preview sync-config`：默认只预览差异；应用时采用 allowlist 和事务，生产端只读、DEV 端写入。无变化 no-op。仅自动新增或更新仍与上次导入一致的来源管理字段；保留 DEV 自定义项及改动，冲突跳过并报告，不自动删除。
- 首次空 DEV 可初始化允许的配置；后续开始开发或更新时可自动检查并同步无冲突项，不自动覆盖冲突。不能实现可靠字段归属判断时退回 diff + 明确覆盖确认，不另建复杂同步平台。
- 全量 reset、覆盖 DEV 修改、导入敏感客户数据不属于自动同步授权，必须单独确认。同步不在两个环境之间双向写回。

上述命令是待实现的操作接口，不是当前可执行命令。优先一个私有脚本的子命令，而非为每项动作创建服务。

## CI 与生产发布

- 纯文档变更只运行相应检查，不触发应用构建或生产重启；构建/运行相关文件不得误归类为文档。
- 复用已有 Go/relaykit 和前端检查；main push 自动检查并构建镜像，DEV 构建按完成批次触发。使用同一构建流程，不为 DEV 每次保存代码构建。
- 前端/后端产物一起发布。主分支最终镜像仍需隔离启动和受影响 smoke，可使用临时容器，不增加常驻环境。
- 主机定时执行小型发布脚本；具体窗口、域名、路径、凭据由私有 OPS runbook 持有。
- 窗口开始时冻结当前 main HEAD 的合格 digest；该 HEAD 未通过构建/检查时本次跳过，不偷选更旧候选。冻结后才合入的新提交进入下个窗口；多个提交只部署该批最新合格版本。
- digest 与运行版本相同则不重启；预拉取成功后仅替换应用，不重启 Docker daemon、数据库、Redis 或整个 Compose 栈。
- 部署锁防止手动/定时任务交错；检查真实运行 digest、健康和消费者路径；失败记录并告警。应用回退仅在数据/config 兼容时恢复 previous-known-good，不能用旧镜像掩盖不可逆迁移。
- 检查启动时自动迁移，不能将“没有独立 migration 文件”当作没有迁移。未验证迁移必须阻断自动发布；不会每天重试一个已知失败 digest。
- 定时器错过窗口不在白天补发；立即发布使用同一个检查/发布脚本。
- 单实例应用更新可能中断在途请求；优先维护窗口，不承诺零停机。未来确有连续可用需求再增加多实例。

完成回执说明：代码版本、测试版本、验证范围、真实调用情况、是否已合入 main、是否待发布/已发布以及阻塞项。不得混淆代码合并、构建完成与生产生效。
